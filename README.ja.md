# OBS Streamkit Demo

[English](README.md) | **日本語**

配信オーバーレイを配信オペレーターの操作画面から切り替えるための、最小構成のサンプルです。使うのは
Vite + React の SPA ひとつと `localStorage` だけ。

1 つのバンドルが、OBS の中で 2 つの顔を持ちます。

- オペレーターが操作する**カスタムブラウザドック**
- 視聴者が見る**ブラウザソース**

ドックで画面を選ぶと、配信に乗っているオーバーレイが即座に切り替わります。サーバーも WebSocket も
OBS プラグインも不要です。

## セットアップ

```bash
pnpm install
pnpm dev
```

<http://localhost:5173/?view=debug> を開いてください。ドックと実寸のオーバーレイプレビューが横に並ぶ
ので、OBS を起動しなくてもオーバーレイを作り込めます。（5173 が使用中なら Vite が次の空きポートに
ずれるので、実際に表示された URL に従ってください。）

## ビュー

1 つのバンドルに 3 つのビューがあり、`src/App.tsx` が `?view=` クエリ文字列で切り替えます。

| URL | 用途 |
| --- | --- |
| `?view=debug` | ドックと 1920x1080 のオーバーレイプレビューを 1 ウィンドウに。開発用。 |
| `?view=dock` | オペレーターの操作画面。OBS のカスタムブラウザドックとして登録する。 |
| `?view=overlay` | 配信に乗せる本番の層。OBS のブラウザソース（1920x1080）として登録する。 |

デバッグ用プレビューはオーバーレイを市松模様の上に描画します。背景の透過が壊れた場合、本番ではなく
この時点で気付けます。

## OBS への登録手順

1. アプリを配信可能な状態にする（`pnpm dev`、または `pnpm build` して `dist/` をホストする）。
2. **ドック -> カスタムブラウザドック...** で `http://localhost:5173/?view=dock` を追加する。
3. シーンに**ブラウザソース**を追加し、URL に `http://localhost:5173/?view=overlay`、幅 **1920**、
   高さ **1080** を指定する。
4. ドックから画面を切り替える。オーバーレイが追随します。

オーバーレイの背景は透過のままなので、OBS が下のシーンに合成します。

## 仕組み

### 2 つのウィンドウ間で状態を共有する

ドックとオーバーレイは OBS の中では別々のブラウザウィンドウなので、React の状態を共有できません。
代わりに `localStorage` のキー `obs-demo:selected-screen` を共有し、`src/lib/storage.ts` がその
読み書きを包んでいます。

`subscribeScreen` は 2 つの経路で購読者に通知します。どちらか片方だけでは両方のケースを賄えないため
です。

- `storage` イベント。**他の**ウィンドウでしか発火しない → OBS 上のドックからオーバーレイへ
- モジュールスコープの購読リスト。**同一**ウィンドウの購読者向け → `?view=debug` 内のドックから
  プレビューへ

2 つめの経路は `setCurrentScreen` が自分で叩きます。したがって書き込む側は必ず `setCurrentScreen`
を通す必要があり、`localStorage` を直接触ってはいけません。

### 1 つのデザインを 2 つのスケールで

ブラウザソースは 1920x1080 で動きますが、開発用の画面には収まりません。スタイルシートを 2 つ持って
同期させる代わりに、オーバーレイのサイズ指定をすべて `rem` で書き、root の font-size にスケールを
担わせています。

```css
html           { font-size: 16px; }  /* ドックと使い方ヒント。素の px の世界 */
html.is-canvas { font-size: 64px; }  /* 1rem = 64px。CSS がそのまま 1920x1080 のキャンバスを表す */
```

`src/main.tsx` が `?view=overlay` と `?view=debug` に `is-canvas` を付けます。環境判定ではなく
**ビュー判定**なので、「どこで開いたか」でオーバーレイのスケールが変わることはありません。

`?view=debug` はステージを 1920x1080 の実寸のまま保ち、画面に収めるための縮小は
`transform: scale()` で**見た目にだけ**掛けます。レイアウトは常に実寸で計算されるため、DevTools が
表示する数値は OBS が実際に描画する数値と一致します。

スタイルを編集するときの約束事: `.overlay` 配下はすべて `rem` で、**キャンバス上の px を 64 で割った
値**を書きます。1 つでも `px` を混ぜるとこの仕組みから外れます。`.dock` や `.debug*` などの外枠は
意図的に `px` のままで、64px の root を継承しないよう各自が `font-size` を宣言しています。

## 画面を追加する

`src/lib/storage.ts` の `screens` が唯一の情報源です。

```ts
export const screens = {
  waiting: { label: "待機画面", title: "WAITING", message: "配信開始までお待ちください" },
  match:   { label: "試合画面", title: "MATCH",   message: "試合中" },
  break:   { label: "休憩画面", title: "BREAK",   message: "しばらくお待ちください" },
} as const;
```

ここに 1 エントリ足せば、ドックの `<select>`、オーバーレイの描画、`ScreenId` 型がすべて自動的に
追随します。追加で必要なのは `src/index.css` の `.overlay-<id>` ルール（配色）だけです。

未知の値や削除された値は `waiting` にフォールバックするので、配信中にオーバーレイが落ちることは
ありません。

## スクリプト

| コマンド | 内容 |
| --- | --- |
| `pnpm dev` | Vite 開発サーバー |
| `pnpm build` | `tsc -b` のあと `vite build` |
| `pnpm lint` | ESLint |
| `pnpm spell` | cspell によるスペルチェック |
| `pnpm check` | 型チェック・lint・スペルチェックをまとめて実行 |
| `pnpm preview` | 本番ビルドを配信 |

テストランナーは設定していません。`pnpm check` が唯一の関門です。

## 技術構成

Vite 8、React 19、TypeScript 6。ルーターも UI フレームワークも状態管理ライブラリも使っていません。
スタイルは `src/index.css` に全部入っています。
